# 1. CRITICAL DATABASE AND AUTHENTICATION RULES

THIS SECTION IS NON-NEGOTIABLE.

**USE SUPABASE AS THE EXCLUSIVE DATABASE AND AUTHENTICATION PLATFORM.**

Do not use Clerk.

Do not use Clerk for authentication, database functionality, user storage, or user management.

Do not use Replit's built-in database, Neon, Firebase, SQLite, or another database provider.

Required infrastructure:

- Supabase PostgreSQL for persistent data
- Supabase Auth for authentication
- Supabase Storage where file uploads are required
- PostgreSQL Row Level Security (RLS)
- Secure server-side database operations
- Environment variables for all credentials and secrets
- SQL migrations for database schema management

All appointments, patient profiles, CRM records, doctor schedules, staff accounts, website content, chat sessions, and operational data must persist in Supabase.

Connect using environment variables such as:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (server-side only)
- `OPENAI_API_KEY` or a configurable AI provider key
- `APP_URL`

Never expose privileged credentials in frontend code.

Never hardcode API keys.

If Supabase credentials are not yet available, prepare the complete integration and migrations, and clearly identify the required environment variables. Do not quietly replace Supabase with another database.

Use real backend operations and secure API authorization. Do not simulate persistence through localStorage or temporary mock arrays.
